# QA V3 bounded evidence loop

QA V3 is an independent feature beside the unchanged legacy project-question API and QA V2. It lets one configured model make at most three structured decisions for one saved project question. A decision either returns one complete claim-bound QA V2 answer, requests narrowly scoped local evidence, asks the user for a missing project file, or stops without an answer.

The feature is an evidence acquisition loop, not a chain-of-thought interface. DeepSeek Reference QA may explicitly enable bounded `low`, `high` or `max` thinking; the default is disabled. CIRP never stores or displays `reasoning_content`, and every safe receipt records `chain_of_thought_included=false`. Only the mode, ordinary usage, bounded decisions, evidence requests and validated answer remain auditable.

## Independent endpoints

- `POST /api/projects/{project_id}/questions-v3/preview` builds the initial transparent page selection and returns loop limits without calling a model.
- `POST /api/projects/{project_id}/questions-v3` runs the bounded decision loop when a non-Mock provider is configured.

The separate browser Reference QA workspace uses these endpoints only after an explicit Reference preparation. The default analysis button and **Ask the project** remain on legacy routes; no legacy or QA V2 route is removed or redirected.

## First-slice tools and bounds

New Reference questions and evaluations now explicitly select v8 (`COMPLETE_SELECTED_SCOPE_V1`). V8 keeps the complete saved source rows and available exact-token layout on selected pages, and expands matching explicit scopes in the same document beyond the four anchor pages. It does not apply the legacy source, layout, row, alias or serialized-input truncation limits below. A read-only audit of the frozen 20 questions found 2,770 initial input rows in v8 with zero selected rows dropped and zero row prefixes clipped; v7 sent 564 rows, omitted 2,206 selected rows and clipped 12 row prefixes at the final context stage. This is transport evidence, not proof that all relevant pages were retrieved or the model understood the relationships. See `reports/kapolei_complete_context_v8_audit_2026-10-03.json`.

V8 uses a separate request identity and receipt v2; v3-v7 evaluations retain their frozen selectors and old request identities. Real provider context limits remain: a recognized context rejection is reported as `MODEL_CONTEXT_LIMIT`, never silently truncated or automatically retried. Decision/output and unresolved-call safety limits remain. The following byte bounds describe **historical v3-v7** only.

The first slice exposes only `FIND_IDENTIFIER` and `SEARCH_TEXT`. Both search immutable parser evidence with the local literal selector; they do not use Canonical data, embeddings, model output or review records and cannot access another project, arbitrary paths, SQL, secrets, code, network or external systems. `FIND_IDENTIFIER` requires an explicit supported Sheet, Section, Paragraph, RFI or Submittal identifier.

One decision may request at most two non-equivalent operations. Three model decisions allow at most two evidence rounds; no new immutable evidence stops locally. Each decision keeps at most 18,000 serialized source-evidence bytes, including metadata and JSON overhead. V5 through v7 may add 6,000 bytes of exact-token layout without evicting source rows. V5/v6 preserve rows and large gaps inside each evidence block; v7 uses the same saved tokens to add one deterministic native-column view across selected blocks on a page. The full request remains within 64 KB, and clipping uses an exact prefix without synthetic citation text. The audit follows the frozen selector: v3 inspects six pages, while v4 through v7 inspect four, all within 48,000 source bytes. It returns version, selection identity, literal scoring, selected identities and limits.

Ordinary decisions cap output at 2,600 tokens; explicit DeepSeek thinking uses 8,000. The frozen profile and request fingerprint include the mode, preventing cross-mode cache reuse.

Non-citable `source_groups` add saved page/order links without copying E text; all 15 zero-call inputs shrank.

Arbitrary pages, model-selected files, version tools, autonomous planning, agents and web search are absent. For image-capable routes, the coordinator attaches at most three already selected pages within 48 MiB; each overview has a stable region and sent-image hash. QA V2 keeps its one-page overview and local crop path.

## Decision and answer contracts

Output is limited to `ANSWER`, `NEED_EVIDENCE`, `NEED_USER_INPUT` or `CANNOT_ANSWER`, with consistent reason, missing facts and requests. The nested claims, calculations and coverage arrays stay empty for non-answers. Before dispatch, CIRP turns only explicit comma lists and parallel clauses into `P1..Pn`; it uses neither evidence nor an answer key, and otherwise keeps one `P1`. Every answer part and emitted claim/calculation must participate in an in-range mapping. Missing, duplicate, empty, out-of-range or unmapped content fails locally.

The provider supplies atomic claims using deterministic input-order `E1..En` or `V1..Vn` aliases plus any requested operator and cited operands; opaque IDs remain local. It does not reproduce quotations, geometry, final answer text or calculated results. CIRP resolves aliases to prompt-visible evidence/regions, joins claims, recomputes with `Decimal`, adds readable arithmetic, builds `project-answer-v2`, then reapplies all QA V2 quote, number, entity and calculation checks. Partial answers cannot pass as complete; an unexplained non-answer receives only a generic local message.

Text and image aliases must exist in the bounded input; CIRP restores exact evidence or audited region identity. Claim numbers and calculation operands must be supported by cited text, calculations must be requested, and explicit Building identity cannot change. Numeric source matching uses Decimal value, so comma, currency and trailing-zero formatting may differ while the value must remain identical. `PERCENT_OF` expands one cited base and one or more cited percentages locally; basic arithmetic, direct extraction, bounded lists and comparisons remain supported. Every calculation citation set must collectively contain all operands, and `layout_lines` remains navigation-only context. Identifier requests include a complete labelled value; descriptive phrases such as a volume cover sheet use text search. Local compilation removes formatting duplication without weakening evidence checks.

The entity check is literal: an explicit compact Building/Bldg target cannot become another building or rely only on citations naming another one. CIRP infers nothing from sheet numbers, file names or general prose.

Each model decision uses a separate audited `answer-v3-r0`, `answer-v3-r1` or `answer-v3-r2` task family. Exact settled lean provider payloads recover from the ledger and are compiled again locally; a malformed, unresolved or settled-without-result call is never automatically retried. A rejected response stores only a bounded validator category such as decision consistency, citation scope, calculation operand support, numeric support or calculation result—not provider output or document text. A frozen evaluation derives that category only when its validated execution receipt points to the matching settled error, and the browser renders the category as plain text. Provider changes remain serialized with the existing application lock.

## Validation performed

Offline tests cover deterministic explicit-list and parallel-clause answer parts, complete/non-empty/in-range part mappings, rejection of unmapped answer content, provider evidence-reference resolution, out-of-scope reference rejection, the stable non-answer shape, local claim joining, Decimal arithmetic, formatting-equivalent source numerics and percentage-of compilation, repeated-request rejection, exact-identifier request boundary, unchanged QA V2 validation, preview/no-call behavior, Canonical-free page selection, coexistence of all three question APIs, one successful two-decision supplementation flow, settled raw-payload recovery, local termination when a request yields no new evidence, and one custom OpenAI-compatible multimodal request with one selected source page, stable hash, locally completed region citation and settled-cache recovery. They also cover granular safe failure-category projection, separate legacy/reference knowledge selection, immutable result persistence, citation normalization, equivalent-result reuse and optimistic-lock review history. MockTransport uses synthetic data and no external provider request or paid call. The fixed 15-question zero-call checklist contains 41 parts; D2/D3/D4 contain 3/3/2 respectively. This proves the contract and rejection behavior, not answer correctness.

Live quality and model-driven visual cropping remain separate gates; exports and local cross-run comparison are implemented. The same-input selector-v7 fixed-15 baseline produced 9 contract-valid / 7 fully usable items for Flash and 12 / 9 for V4 Pro, so both failed the release gate. The later frozen 20-question Flash A/B improved contract validity from 14/20 to 17/20 and Kapolei fully usable answers from 8/15 to 10/15 with `thinking-low`, but doubled mean latency. Contract validity remains distinct from correctness; detailed historical runs stay in dated reports.
