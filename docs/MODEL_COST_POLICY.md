# 低成本模型、token与预算策略
**规格版本：** 0.2.1

## 1. 任务路由
| 级别 | 执行者 | 任务 | 默认上限 | 升级条件 |
|---|---|---|---|---|
| L0 | 普通代码 | 哈希、MIME、编号正则、单位换算、数量合计、Schema、导出 | 0 LLM token | 无规则可可靠决定的语义问题 |
| L1 | Flash非思考 | 分类、材料/QA/报告联合抽取、简单候选验证 | 单次6k输入、2k输出 | 证据完整但局部关系不清 |
| L2 | 同Flash思考low | 跨来源关系、难归并、矛盾判别 | 单次12k输入、4k输出（含推理预算） | 配额内仍不能解决则人工或已批准L3 |
| LV | 专用视觉候选 | 字符OCR不足、表格图像、符号/Leader/Detail | 初始每次2个局部图、2k输出 | 能力未验证则阻断，不回退假装看图 |
| L3 | 可配置较强模型 | 少量L2失败且高价值的疑难任务 | 默认关闭 | 负责人批准模型、价格和启用策略 |

DeepSeek当前文档说明思考默认开启，因此L1必须显式禁用；L2才开启低强度。官方普通Flash为文本路由，视觉用独立vision-exp候选；实际用户API仍需探针。[S1][S2]

不规定“90%走小模型”为事实，记录各层调用次数、输入/输出/推理tokens和费用，后续根据真实项目调配。简单任务不得默认先经过大模型规划再交小模型，这会抵消节省。

## 2. 首读一次，复用事实
每个语义片段首次调用同时抽取材料、测试和报告原子候选。实体归并、最新值、字段校验用代码先做，只有模糊部分交模型。四类最终表由已存数据投影，不再分别通读全套图纸。

首读保持完整遍历。分类、检索和低优先级不能成为永久跳过一页的理由。长段超过上限时按段落/表格行分块，重复必要上级条件并保留Source ID。返回过长、finish_reason=length或空对象时，保留进度并拆分，不悄悄截掉后半清单。

## 3. 上下文与输出
输入顺序：稳定system规则→该任务最小JSON结构→项目/单位/版本元数据→当前原文及必要父条款→相关短证据。只读相关上下文，不携带完整聊天历史。条件、否定、标准号、尺寸、单位、日期、图例和脚注不可当噪声删除。

输出只含短结构字段、证据ID和简短支持理由，不输出思维链、长摘要或重复原文。模型字段ID只在获准Evidence清单内选择，服务端再检查。API不支持严格Schema时用JSON模式+本地验证，不假设JSON语法合法就满足业务要求。[S3]

## 4. 修复与升级预算
语法错误：先本地解析/校验，不用LLM格式化有效JSON。必要时最多一次局部修复，发送失败字段及对应原文，不重新发送整项目。仍失败且证据足够才允许一次L2，总逻辑任务模型调用初值不超过3次。

限流或网络超时属于传输问题，不自动换贵模型。按429/5xx策略退避且重试也占费用；请求是否计费不明时预留不释放。证据不存在、图纸缺比例、供应商未开通视觉，都不是升级推理强度的理由。

## 5. 两层缓存
应用缓存命中可以完全免去API调用。键必须含tenant、project、输入快照、源片段及局部图哈希、解析器、Prompt、模型别名/已知版本、Schema、检索、Assembly、最新规则和执行参数。人工判定与模型候选分别存放。

供应商前缀缓存不等于应用结果缓存。官方缓存按前缀匹配且不保证命中；可以减少费用，但预算先假定未命中，收到usage后核销。[S4] 不为凑缓存给请求增加无关文本。

## 6. 预算公式
C = 未命中输入tokens×对应单价/1,000,000 + 命中输入tokens×单价/1,000,000 + 输出总tokens×单价/1,000,000 + OCR/CAD/直接计算。

输出总tokens包含供应商计入其中的推理tokens时不得再次相加。视觉按真实图片tokens/服务费用估算。不能按PDF字节数线性推算tokens；未知图像计费需要能力探针或可信上界，未建立上界不发收费请求。

本次官方参考快照（2026-09-08，高峰CNY/百万token）：Flash和视觉候选输入未命中3、命中0.10、输出9；Pro为9/0.30/27。只用于规格里的保守示例，用户接口价格未确认，不能直接启用。[S5]

纯文本假设示例：10M未命中输入+1M总输出，Flash费用=30+9=39元；不含OCR、CAD和其他计算。它不代表10GB项目价格，也不代表已测效果。

## 7. 原子费用闸门
累计spent + outstanding_reservations（包含待对账费用，不重复相加）+ next_upper_bound ≤ 300CNY。每次发请求之前在数据库事务中预留最坏成本；并发Worker不得各自读余额然后无锁消费。

完成后按usage结算，缓存优惠退回差额。超时等待对账，不能假定0费用后重新花掉。收费超过预留时记录实际费用并冻结后续调用，不丢弃账单。价格改变、第三方附加费或估算错误可使实际值超过预估，不能宣传软件能够退回外部已收费金额。

初始剩余20%预警是工程配置。到预算或24小时目标边界，暂停新增任务、列剩余清单、待负责人批准。只有明确新额度才继续，不自动扩到10k。

## 8. 原型能力与开发LLM
本包参考代码仅离线实现路由决策和内存预算模型，生产需要持久化事务、账单对账和取消协议。没有使用用户API产生训练、批量文档分析或费用。

开发过程也采用L0工具优先：格式化、Schema生成、运行测试不交大模型。低价开发代理接收一张小任务卡，限定需求ID、文件范围、测试和token预算；架构/状态规则修改需负责人审批。当前会话没有调用外部子模型的能力或凭证，因此不声称本轮生成已实际委派低价模型。
