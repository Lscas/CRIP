# 低成本模型、token与预算策略
**规格版本：** 0.2.1

## 1. 任务路由
| 级别 | 执行者 | 任务 | 默认上限 | 升级条件 |
|---|---|---|---|---|
| L0 | 普通代码 | 哈希、MIME、编号正则、单位换算、数量合计、Schema、导出 | 0 LLM token | 无规则可可靠决定的语义问题 |
| L1 | Flash最低推理 | 分类、材料/QA/报告联合抽取、简单候选验证 | 文本抽取最多32k UTF-8输入字节工程估算、8k输出 | 证据完整但局部关系不清 |
| L2 | 同Flash思考low | 跨来源关系、难归并、矛盾判别 | 单次12k输入、4k输出（含推理预算） | 配额内仍不能解决则人工或已批准L3 |
| LV | DeepSeek 专用视觉候选 | 字符OCR不足、表格图像、符号/Leader/Detail | 当前单张可见整页 PNG（最长边2048）、最多2k输出 | 能力未验证则阻断，不回退假装看图；局部高分辨率裁剪尚未实现 |
| L3 | 可配置较强模型 | 少量L2失败且高价值的疑难任务 | 默认关闭 | 负责人批准模型、价格和启用策略 |

DeepSeek当前文档说明思考默认开启，因此L1必须显式禁用。Gemini 3.6 Flash不能关闭推理，用户明确选择该供应商时L1固定`reasoning_effort=minimal`，推理token按输出计费且受`max_tokens`总生成上限约束；L2提高强度仍需另行实现。官方模型能力不代表施工准确率，实际用户API仍需小样例验证。[S1][S2][S8][S9]

不规定“90%走小模型”为事实，记录各层调用次数、输入/输出/推理tokens和费用，后续根据真实项目调配。简单任务不得默认先经过大模型规划再交小模型，这会抵消节省。

## 2. 首读一次，复用事实
每个语义片段首次调用同时抽取材料、测试和报告原子候选。实体归并、最新值、字段校验用代码先做，只有模糊部分交模型。四类最终表由已存数据投影，不再分别通读全套图纸。

首读保持完整遍历。分类、检索和低优先级不能成为永久跳过一页的理由。长段超过上限时按段落/表格行分块，重复必要上级条件并保留Source ID。文本抽取请求采用最多32,000 UTF-8字节的保守工程包络，它不是实际token计数；返回过长、finish_reason=length或空对象时，保留进度并失败关闭，不悄悄截掉后半清单，也不自动再次收费。

## 3. 上下文与输出
输入顺序：稳定system规则→该任务最小JSON结构→项目/单位/版本元数据→当前原文及必要父条款→相关短证据。只读相关上下文，不携带完整聊天历史。条件、否定、标准号、尺寸、单位、日期、图例和脚注不可当噪声删除。

输出只含短结构字段、证据ID和简短支持理由，不请求或保存思维链、长摘要或重复原文。文本联合抽取最多8,000生成token；页面视觉仍最多2,000，字段核验仍最多1,400，且三者都不得超过运行时`Settings.output_limit`。模型字段ID只在获准Evidence清单内选择，服务端再检查；人工重排的generation后缀属于内部账务键，不进入模型Evidence ID。除保守去除UTF-8 BOM、完整Markdown JSON围栏或单个JSON对象前后的短白名单化展示语外，契约修复仅允许不发明施工事实的降级操作：移除根级多余字段、保持数字/布尔属性值为等值字符串、修复重复局部键和悬空父引用，或舍弃无法完整验证的原子项。任何契约修复都把结果标为`TRUNCATED`并进入人工审核；多对象、未知前后文字、越界/缺失证据、审核结论字段或未知嵌套字段仍拒绝发布。[S3]

字段核验另允许移除模型回显的已知输入字段`claim`、`label`、`evidence_ids`、`context`，以及把过长理由替换为有界说明；这类修复不改变引用、路径或施工事实，并强制把该字段降为`NEEDS_CONTEXT`。其他未知字段、非法状态、错误路径、越界证据或非逐字引用仍记账后拒绝通过。候选的显示用审核摘要限制为400字符；完整抽取属性仍保存在证据中，不以截短摘要替代原始输出。

## 4. 修复与升级预算
语法错误：先本地解析/校验，不用LLM格式化有效JSON。必要时最多一次局部修复，发送失败字段及对应原文，不重新发送整项目。仍失败且证据足够才允许一次L2，总逻辑任务模型调用初值不超过3次。当前恢复协议把文本提取、页面视觉和语义核验都按稳定任务族计数；只有人工对账后的显式Resume/新核验任务或专用视觉重排能创建新generation，gen0至gen2合计最多3次。

限流或网络超时属于传输问题，不自动换贵模型。HTTP状态先安全分类：400/401/403/404阻断并检查请求或账户；408、429和5xx提示可等待的暂时类错误及合规`Retry-After`，但不自动再次收费。Gemini本机live默认两次请求开始至少间隔15秒，减少突发但不绕过供应商配额。任何人工重试仍占费用；请求是否计费不明时预留不释放。诊断只保存状态、短机器码及格式受限的请求标识，不保存响应正文、文档内容或密钥。证据不存在、图纸缺比例、供应商未开通视觉，都不是升级推理强度的理由。

## 5. 两层缓存
应用缓存命中可以完全免去API调用。键必须含tenant、project、输入快照、源片段及局部图哈希、解析器、Prompt、模型别名/已知版本、Schema、检索、Assembly、最新规则和执行参数。人工判定与模型候选分别存放。

供应商前缀缓存不等于应用结果缓存。官方缓存按前缀匹配且不保证命中；可以减少费用，但预算先假定未命中，收到usage后核销。[S4] 不为凑缓存给请求增加无关文本。

## 6. 预算公式
C = 未命中输入tokens×对应单价/1,000,000 + 命中输入tokens×单价/1,000,000 + 输出总tokens×单价/1,000,000 + OCR/CAD/直接计算。

输出总tokens包含供应商计入其中的推理tokens时不得再次相加。视觉按真实图片tokens/服务费用估算。DeepSeek V4 Flash Vision当前官方说明每张图像最多384图像token；本版再为Prompt、Schema、定位元数据和输出分别保守预留，并与文本共用用户选择的项目闸门。不能按PDF字节数线性推算tokens；未知图像计费需要能力探针或可信上界，未建立上界不发收费请求。本机RapidOCR、PDF矢量读取和ezdxf/LibreDWG不产生供应商API费用，但仍消耗本机时间和内存。

DeepSeek官方参考快照（2026-09-11，峰值USD/百万token）：V4 Flash与视觉实验版输入未命中$0.44、命中$0.014、输出$1.32；Pro为$1.32/$0.044/$3.96。DeepSeek安全启动器用固定10 CNY/USD安全倍数，对V4 Flash预留输入¥4.40、输出¥13.20；这不是报价或实时汇率。Gemini 3.6 Flash Standard参考快照（2026-09-10，USD/百万token，截至2026-12-31）：输入0.75、输出3.75且输出含thinking。[S5][S10]

按上述DeepSeek内部人民币安全上界，纯文本假设示例：10M未命中输入+1M总输出，预留上界=44+13.2=57.2元；不含OCR、CAD和其他计算。它不代表10GB项目价格，也不代表已测效果或实际账单。

## 7. 原子费用闸门
累计spent + outstanding_reservations（包含待对账费用，不重复相加）+ next_upper_bound ≤ user_selected_project_limit。新项目默认300CNY；用户可在0.01至1,000,000CNY范围内修改，但不能低于已结算与未结算预留之和。每次变更留审计记录。每次发请求之前在数据库事务中预留最坏成本；并发Worker不得各自读余额然后无锁消费。

完成后按可信usage和已确认的保守输入/输出费率结算；本版不自动推断供应商缓存折扣，也不因推测命中而退回本机预算差额，最终以人工核对供应商账单为准。对于已取得可信usage的响应，实际费用、供应商请求号、规范化有效结果及应用缓存必须在同一个SQLite写事务提交；契约失败则由同一事务提交实际费用和不含原始正文的安全终态诊断。进程在提交后、业务状态更新前中断时，同一付费任务从终态恢复，不再发送HTTP。只有带审计历史的新付费代次才是显式重排，原调用不会覆盖或删除。超时等待对账，不能假定0费用后重新花掉。收费超过预留时记录实际费用并冻结后续调用，不丢弃账单。价格改变、第三方附加费或估算错误可使实际值超过预估，不能宣传软件能够退回外部已收费金额。

初始剩余20%预警是工程配置。到预算或24小时目标边界，暂停新增任务并列剩余清单。只有本机用户明确保存新的项目额度才继续，不自动增加上限。

## 8. 原型能力与开发LLM
当前应用已使用持久化事务实现费用预留、结算和人工对账审计，但仍不会自动读取供应商账单，也没有供应商取消协议。未知调用只有在用户确认已查账单后才能登记为0或实际人民币费用；原调用及对账事件永久保留，实际超过预留会冻结预算。2026-09-11三次有界Gemini live验证已经产生用户API费用：合成项目结算¥0.007605；Gemini真实PDF首次运行及用户授权重试累计结算¥0.526795，并保留¥0.237238未决预留。该Gemini项目最多只处理7/144个片段。2026-09-13独立DeepSeek合并项目完成指定59页图纸与833页规格书的2/2文件、1,964条证据和10,926份核验，8,501次调用全部结算为¥107.047278，预留/未知/未决均为0，可用预算¥192.952722。各项目预算独立；本应用只发起推理请求，没有实现训练流程，供应商如何处理请求数据及最终账单仍以用户账户对应条款为准。

开发过程也采用L0工具优先：格式化、Schema生成、运行测试不交大模型。低价开发代理接收一张小任务卡，限定需求ID、文件范围、测试和token预算；架构/状态规则修改需负责人审批。当前会话没有调用外部子模型的能力或凭证，因此不声称本轮生成已实际委派低价模型。
