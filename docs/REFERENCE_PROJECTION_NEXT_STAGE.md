### 阶段3第一切片：原因来源分离

本轮架构审查固定新路径为decision2、loop2、receipt6、proof3、execution2与failure2；selector10、原PDF stage1、append-only context V1和review packet2保持不变。现有无参内部helper默认loop1；新路径必须显式选择loop2。旧prompt/schema不改，旧实际请求、缓存、账本身份不漂移。新旧proof、receipt、失败链禁止混用，并须在预留费用或HTTP前拒绝。

三个不同的终态不可互换：

- 模型发现需要资料：`NEED_EVIDENCE`，交由本地执行经过认证的检索请求。
- 本地实际补证新增页为零：应用生成`CANNOT_ANSWER/NO_NEW_EVIDENCE`，依据为`PROJECTION_LOCAL_RETRIEVAL_EXHAUSTED`；模型无权输出这一原因。
- 第三次判断仍不足以支持题目：模型可以返回`CANNOT_ANSWER/INSUFFICIENT_EVIDENCE`，仅剩余决策数为1且`projection_complete is True`时合法，依据仍为`PROJECTION_LOOP_TERMINAL`；不能把解析缺口归为资料不足、把补证轮次用完称为检索已穷尽，也不能凭空宣称缺文件。

先通过新旧身份、错误结算与零HTTP恢复、有效补证再零新增等实际调用链测试，再接入统一`reference_results`保存。后者需要纯本地来源/账本认证、历史行与外键不变的原子迁移，以及每次读取重新认证。没有新的平行结果库。公开入口、case与评测接入分别验收，不能借用旧v9开关自动开放。

## 新模型合同

- `REVIEW_REQUIRED`：只能选择 1–4 个完整 X 行并映射题目部分；输出本地生成、不含原文的复核定位包，不生成 claims／施工答案。缺少真实关系验证，不能写入人工批准。
- `NEED_EVIDENCE`：最多两个已有本地检索请求，必须指出缺什么，不能重复请求。
- `NEED_USER_INPUT`：确实缺文件或原文件不可读。已有文件的几何解析缺口不能冒称文件缺失。
- `CANNOT_ANSWER`：模型只可报告冲突、不支持、投影不完整，或最后一次判断仍证据不足；无新增来源只能由本地实际补证结果产生。不得用猜测补齐。

所有选中行保留完整输入。旧公共答案长度限制不裁剪来源，也不阻止只引用长行供人工复核；真实提供方硬容量不足时明确报错，不静默截断。X 是当前来源包的本地别名，不是历史数据库 E 引用。每次执行认证项目、run、snapshot、文档指纹、页码、投影、问题及题目部分；输入回执只留哈希与计量，不留原文或思维链。

## Prompt 参考与采用方式

用户提供的 [system_prompts_leaks](https://github.com/asgeirtj/system_prompts_leaks) 仅作为公开模式索引；社区收集内容不是官方真实性或安全承诺，不复制整段泄漏提示、产品身份或工具权限。新 prompt 自行编写，采用指令／资料分层、明确缺失判断、封闭动作、窄检索及结构化返回。

[Google 官方提示设计说明](https://ai.google.dev/gemini-api/docs/prompting-strategies) 支持明确指令和上下文分隔；[OpenAI 官方提示工程说明](https://developers.openai.com/api/docs/guides/prompt-engineering) 可参考版本化与评测方法。此处借鉴通用组织方法，不把第三方示例当作模型效果证据。安全边界由 schema、本地校验、原 PDF 重认证和账本落实，不能依赖模型自报“有把握”。

Prompt 必须与 schema 一起冻结哈希；同输入比较时固定版本。缺失信息只保留题目部分引用与枚举缺口码，不能夹带自由答案；不索取／保存隐藏 CoT。旧 prompt 不修改，避免历史重放身份漂移。实际发送的 JSON 必须与本地构造的完整规范输入逐字一致，不接受额外提示、评分答案键或重复 JSON 字段。
